What is Observability?
Observability is the ability to understand the internal state of system or health of a system by analyzing the data generated by the three pillars of observability—logs, metrics, and traces.

Here system means (Application + Infrastructure + network).

Observability tells us what is happening, why it is happening and how it is happening.
	• What's happening - By looking/monitoring the metrics we can say what is happening?
	• Why it's happening - By looking into logs we can say why this is happening
	• How it's happening - And by looking at traces we can say how it is happening.

What is metrics? 
Metrics will give you period/historical data of events. 
Metrics involves tracking system metrics like CPU usage, memory usage, and network performance. Provides alerts based on predefined thresholds and conditions.

What is logging?
Logs involves the collection of log data from various components of a system.
There are different types of logs like
	• Information logs
	• Warning logs
	• Error logs
	• Debug logs
	
What is traces?
Traces will give us extensive information to debug troubleshoot as well as fix the issue
Traces tracks the entire flow of a request as it moves through different services and components within a system.
 
D/B observability and monitoring?
Monitoring is a sub-part of observability, monitoring only focuses on one pillar of observability.

What monitoring is?
Basically Monitoring helps us keep an eye on our systems to ensure they are working properly.
So along with Metrics if we configure alerts, and some fancy dashboard that is what called as Monitoring. 
We can send an alerts on slack, email or etc.
And we can configure dashboard on Grafana
In short: Monitoring = Metrics + alerts + dashboards

Why Monitoring system are required?
So, the one problem with metrics is metrics is a raw data, by looking into it we can't say anything. So, what we are doing is, we are feeding this raw data into some monitoring system like Prometheus, which is correctly one of the good monitoring system. It's very popular open-source monitoring tool in the world of Kubernetes.

Now what this monitoring system will do is, it will represents this data in graphical format on a dashboard, which we would easy to read.

Also what else we can do in monitoring system is configuring the alerts, when there is a spike or something went wrong.

What is Monitoring system?
Monitoring system will collects the metrics or pull or scrap the metrics and represents the same in graphical format.

D/B Monitoring and Metrics:
Monitoring is a superset where it has metrics, dashboards and alert mechanism


Why observability is important or necessary?
Setting up good observability is crucial because it makes the application more robust and reliable, increasing its value and marketability and also observability make it easier to maintain. Observability will boosts customer trust, also makes the application more attractive and competitive in the market. 
Because in real world, we will sign some SLA i.e. Service Level Agreements with our clients. And we should make sure it should not breach at any cost.
That's why every modern applications these days needs observability.


Is observability Developer's responsibility or DevOps responsibility?
In a real world observability is a collective efforts.

What are the developer's responsibilities?
	• Will writing the application its developer's responsibility to instrument the metrics, that means that application will throw some metrics.
	• Developer should write the logs like what information, what fields that log must have and likewise
	• Developer should also implement the Traces.

What are the DevOps's responsibility?
	• DevOps's responsibilities are to collect the data generated by these three pillars, store it for analysis purpose.
	• Create alerts and dashboards to monitor the system.
	• Detect issues, debug logs, fix issues, if there is code change then escalate that to developer.
