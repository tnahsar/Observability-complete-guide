# How to Capture Infrastructure Metrics & Logs

---

## 1️⃣ First: What Do We Mean by “Infrastructure”?

“Infrastructure” includes:

* Kubernetes cluster
* Control plane
* Worker nodes
* Pods & containers
* Underlying OS
* Network & storage

Each layer exposes **metrics** and **logs** differently.

---

## PART A: Capturing Infrastructure **Metrics**

Metrics are **pulled or pushed numeric data** collected at intervals.

---

## 2️⃣ Metrics Collection Architecture (High Level)

```
Infrastructure → Exporters → Metrics Backend → Dashboards / Alerts
```

In Kubernetes, the **industry standard backend** is **Prometheus**.

---

## 3️⃣ Cluster & Control Plane Metrics

### 🔹 What Captures Them?

* Kubernetes control plane exposes `/metrics` endpoints

### 🔹 How They Are Collected?

* **Prometheus scrapes**:

  * kube-apiserver
  * kube-scheduler
  * kube-controller-manager
  * etcd

📌 In managed Kubernetes (EKS/GKE):

* Some metrics are abstracted
* Available via:

  * CloudWatch
  * Managed Prometheus

---

## 4️⃣ Node-Level Metrics

### 🔹 What Metrics?

* CPU, memory, disk, network
* Node conditions

### 🔹 Tool Used: **Node Exporter**

📌 Node Exporter:

* Runs as **DaemonSet**
* One pod per node
* Exposes OS-level metrics

```
Node → Node Exporter → Prometheus
```

---

## 5️⃣ Pod & Container Metrics

### 🔹 What Metrics?

* Container CPU & memory
* Restarts
* OOMKills
* Throttling

### 🔹 Tool Used:

* **kubelet + cAdvisor**

📌 kubelet exposes container metrics
📌 Prometheus scrapes kubelet endpoints

---

## 6️⃣ Kubernetes Object State Metrics

### 🔹 What Metrics?

* Pod status
* Deployment replicas
* Node readiness

### 🔹 Tool Used: **kube-state-metrics**

📌 Important:

> kube-state-metrics does NOT measure usage
> It reports Kubernetes object states

---

## 7️⃣ Application-Level Metrics (Infrastructure Adjacent)

### 🔹 Tooling:

* Prometheus client libraries
* OpenTelemetry SDKs

📌 Metrics:

* Request count
* Error rate
* Latency

---

## 8️⃣ Metrics Summary (Must Remember)

| Layer           | Tool                     |
| --------------- | ------------------------ |
| Control plane   | Native metrics endpoints |
| Node            | Node Exporter            |
| Pod / Container | kubelet / cAdvisor       |
| K8s objects     | kube-state-metrics       |
| App             | Prometheus / OTel SDK    |

---

## PART B: Capturing Infrastructure **Logs**

Logs are **event-based** and **pushed**, not scraped.

---

## 9️⃣ Logs Collection Architecture (High Level)

```
Infrastructure → Log Agent → Log Backend → Search / Alerts
```

Common backend:

* Elasticsearch
* OpenSearch
* CloudWatch Logs
* Loki

---

## 🔟 Node & OS Logs

### 🔹 What Logs?

* syslog
* kernel logs
* kubelet logs
* container runtime logs

### 🔹 Tool Used:

* **Fluent Bit / Fluentd**

📌 Runs as:

* DaemonSet
* Reads log files from node filesystem

---

## 1️⃣1️⃣ Container & Pod Logs

### 🔹 What Logs?

* Application stdout/stderr
* Init container logs

📌 Kubernetes writes container logs to:

```
/var/log/containers/
```

### 🔹 Collection:

* Fluent Bit reads these files
* Adds metadata (namespace, pod, container)
* Sends to backend

---

## 1️⃣2️⃣ Control Plane Logs

### 🔹 What Logs?

* API server logs
* Scheduler logs
* Controller logs
* etcd logs

📌 Access depends on:

* Self-managed K8s → Fluent Bit
* Managed K8s → Cloud provider logging

---

## 1️⃣3️⃣ Log Processing & Enrichment

Log agents can:

* Parse JSON
* Add Kubernetes metadata
* Filter noise
* Mask sensitive data

📌 Example:

* Drop debug logs
* Mask passwords

---

## 1️⃣4️⃣ Logs Summary (Must Remember)

| Layer           | Tool                    |
| --------------- | ----------------------- |
| Control plane   | Cloud logs / Fluent Bit |
| Node            | Fluent Bit              |
| Pod / Container | Fluent Bit              |
| Application     | stdout/stderr           |

---

## 1️⃣5️⃣ Metrics vs Logs (Final Mental Model)

| Metrics    | Logs      |
| ---------- | --------- |
| Pulled     | Pushed    |
| Numeric    | Textual   |
| Aggregated | Detailed  |
| Alerts     | Debugging |

---

## 1️⃣6️⃣ Real-World Kubernetes Observability Stack

Most common stack:

* **Prometheus** → Metrics
* **Alertmanager** → Alerts
* **Grafana** → Dashboards
* **Fluent Bit** → Logs
* **Elasticsearch / Loki** → Log storage
* **OpenTelemetry** → Unified instrumentation

---

## 1️⃣7️⃣ Interview One-Liner

> *Infrastructure metrics are captured using exporters like node-exporter, kube-state-metrics, and kubelet, while infrastructure logs are collected using log agents like Fluent Bit running as DaemonSets and sent to centralized log backends.*
